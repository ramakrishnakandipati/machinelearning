# Hospitality CLTV - 12-Month Guest Lifetime Value Scoring

## 1. Purpose

Predicts the **next-12-month revenue (CLTV)** of hotel loyalty guests from their stay history. The pipeline generates a synthetic guest/booking dataset, builds leakage-safe calibration-window features, trains seven CLTV paradigms plus a top-3 ensemble, evaluates them on a held-out test split, produces plots, and serves predictions through a FastAPI app (single guest, batch cohort, SHAP drivers, value tiers).

- **Problem:** rank and size guest value for a zero-inflated target (68.0% of guests spend nothing in the horizon, see `output/logs/execution.log`).
- **Capabilities:** BG/NBD + Gamma-Gamma baseline, XGBoost/CatBoost Tweedie, LightGBM hurdle, FT-Transformer (ZILN), GRU + attention (ZILN), neural Weibull survival; validation-based best-model selection; tier cut-offs (VIP/High/Medium/At-Risk); REST API with JSONL telemetry.
- **Users:** CRM / loyalty analytics, revenue management, data scientists.

## 4. Architecture & data flow

```
config.yaml -> data_generator.generate -> guests/bookings.parquet
   -> features.build_dataset (cutoff = calibration_months; 12-month target; seq tensors)
   -> train.train_all (7 models) -> predictions.parquet (val+test)
   -> evaluate.evaluate_all (metrics, top-3 ensemble, best model, tier cutoffs)
   -> visualize (eda / features+SHAP / training loss / comparisons)
   -> capture_api_screenshots (Uvicorn + Playwright)
output/models + logs -> src.api (FastAPI): /health, /predict/guest, /predict/batch
```

## 5. Prerequisites & setup

- Python 3 (cached bytecode is cpython-312); GPU optional (`gpu.enabled: true`, falls back to CPU). Observed run: RTX 3090, torch 2.15.0+cu132.
- Install: `pip install -r requirements.txt`; for screenshots also `playwright install chromium` (Playwright is used headless Chromium per script docstring).
- Key pins (minimums): numpy>=2.0, pandas>=2.2, torch>=2.3, xgboost>=2.1, lightgbm>=4.3, catboost>=1.2, shap>=0.45, fastapi>=0.110, pydantic>=2.6.

## 7. Usage

```
python run_pipeline.py                      # full pipeline + API screenshots
python run_pipeline.py --n-guests 2000      # smoke test (target_bookings = 4.4 x guests)
python run_pipeline.py --skip-screenshots
uvicorn src.api:app --host 127.0.0.1 --port 8000   # serve (needs trained output/models)
```

API: `GET /health`, `POST /predict/guest`, `POST /predict/batch` (max 20,000 guests; `model` = best | ensemble | model name; `include_shap`). Artifacts land in `output/` (models, logs, plots, data, api_screenshots). There is no test suite; `run_pipeline.py` verifies a REQUIRED artifact list and returns exit code 1 if any is missing.
