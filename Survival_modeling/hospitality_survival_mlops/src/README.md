# src - Survival pipeline & API package

## 1. Purpose & scope
Python package (`src.*`, run with `python -m src.<module>` from the project root) that owns the whole survival workflow: synthetic data generation, EDA plots, feature engineering, ten survival models behind one interface, Optuna tuning, hold-out evaluation, best-model selection, model persistence and the FastAPI inference service.
It delegates configuration to `../config/config.yaml`, and reads or writes data and artifacts under `../data` and `../output`. API tests and screenshot capture live in `../tests`.

## 3. Metrics & health
**Code metrics (static count):** 13 `.py` files (including `__init__.py`), 10 survival model classes, 1 API app with 2 endpoints. Tests for this package: 3 test cases in `../tests/test_api.py` (API only; there are no unit tests for models, features, or evaluation).

| Metric | Definition | Observed value / threshold | Where defined / output |
|---|---|---|---|
| Harrell C-index | `concordance_index_censored` on the test set | Logged at runtime; best observed 0.6898 (xgboost_aft) | `evaluate.evaluate_model` -> `output/training_logs/model_comparison.csv` |
| Uno C-index (IPCW) | `concordance_index_ipcw`, tau = min(max test time, max train time) | Best observed 0.6712 (xgboost_aft); used for model selection | `evaluate.py`, `best_model.json` |
| Integrated Brier Score | `integrated_brier_score` over a grid from `eval_grid_min` to `eval_grid_max` (12 points) | Selection gate: IBS < 0.25 (`train_pipeline.py`); winner IBS 0.1983 | `evaluate.py` |
| Time-dependent AUC | `cumulative_dynamic_auc` using 1 - S(t\|x); 30/90/180/365 d plus mean | Logged at runtime | `evaluate.py` |
| Tuning validation C | Harrell C on a stratified 20% inner split of the train set | Logged at runtime; `val_c_index` in `metrics_summary.json` | `train_pipeline.tune` |
| CoxPH PH-test | Proportional-hazards test, alpha 0.01 | Logged at runtime | `coxph_proportional_hazards_test.csv` |
| Train seconds | Per-model fit time | Logged at runtime | `model_comparison.csv` |

## 4. Key files & components
| File | Main classes / functions | Responsibility |
|---|---|---|
| `utils.py` | `load_config`, `resolve`, `get_logger`, `get_device`, `seed_everything`, `timer`, `make_surv_array`, `FEATURE_COLUMNS`, `TIERS` | Config, logging (stdout plus `output/training_logs/pipeline.log`), CUDA detection with CPU fallback, seeding |
| `data_generator.py` | `generate`, `_simulate_features`, `_event_times`, `_tune_censoring`, `main` | Weibull-AFT synthetic guests with a deliberate PH violation and bisection-tuned censoring; CLI `--config`, `--n` |
| `eda_visuals.py` | `run`, `plot_km_by`, `plot_nelson_aalen`, `plot_censoring`, `plot_correlation`, `plot_violins` | 6 EDA PNGs to `output/data_visuals` |
| `features.py` | `engineer`, `Preprocessor`, `load_and_split` | 17 model features (5 binary, 12 continuous; log, RFM, interaction, engagement); standard scaling; split stratified by event and duration quartile |
| `base.py` | `SurvivalModel`, `monotone_survival`, `median_from_curve`, `breslow_baseline`, `breslow_survival` | Common interface: `fit`, `risk`, `survival`, `save`, `load` |
| `models_classical.py` | `KaplanMeierModel`, `NelsonAalenModel`, `CoxPHModel`, `WeibullAFTModel`, `LogNormalAFTModel` | lifelines baselines and parametric models |
| `models_tree.py` | `RSFModel`, `XGBSurvivalModel` (cox / aft) | scikit-survival forest; GPU XGBoost survival |
| `models_deep.py` | `DeepSurvModel`, `DeepHitModel`, `neg_log_partial_likelihood`, `deephit_loss` | PyTorch MLPs, early stopping, loss history CSV |
| `registry.py` | `ARTIFACTS`, `BASELINES`, `load_model` | Maps model name to artifact file; reloads the winner |
| `evaluate.py` | `evaluate_model`, `metrics_table`, `plot_*`, `PERSONAS` | Metrics and 6 comparison plots (SHAP, calibration at 180 d, persona curves, and so on) |
| `train_pipeline.py` | `tune`, `build_final_models`, `run` | Orchestrator; CLI `--config`, `--quick`, `--n`; writes `best_model.json`, `metrics_summary.json` |
| `api.py` | `app`, `GuestProfile`, `SurvivalResponse`, `recommend`, `lifespan` | `GET /health`; `POST /predict/survival` (503 if the model is not loaded, 422 on validation errors) |

## 5. Inputs, outputs & dependencies
| Kind | Item |
|---|---|
| Inputs | `config/config.yaml`; `data/guests.csv` (generated by the pipeline; read by the API for a 3000-row risk reference sample) |
| Outputs | `output/models/*` (model artifacts, `preprocessor.pkl`, `best_model.json`); `output/training_logs/*` (Optuna CSVs, `model_comparison.csv`, `metrics_summary.json`, loss histories, `pipeline.log`); `output/data_visuals`, `output/comparison_graphs` |
| Dependencies | numpy, pandas, scipy, scikit-learn, scikit-survival, lifelines, xgboost, torch, optuna, shap, matplotlib, seaborn, PyYAML, joblib, fastapi, pydantic (see `../requirements.txt`) |
| Env vars | None read; the config path comes from the `--config` flag |

## 6. Usage & verification
```text
# from the project root
python -m src.data_generator --n 15000
python -m src.train_pipeline            # full run (config defaults)
python -m src.train_pipeline --quick    # smoke test: N=3000, 2 Optuna trials per model
uvicorn src.api:app --host 127.0.0.1 --port 8000
pytest -q tests/test_api.py             # needs output/models/best_model.json
```
