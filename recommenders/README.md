# Recommenders

## Purpose

Five retail/e-commerce recommender sub-projects that explore the same problem from different angles: classic item-based collaborative filtering, a GPU two-tower retrieval model with ANN serving, and three **cold-start** approaches (hybrid meta-router, semantic IDs via VQ/RQ-VAE, and a unified representation-learning space). Each is a self-contained, runnable project with its own config, tests/verification, outputs and FastAPI service.

## Subfolders at This Level

| Subfolder | Core purpose | High-level metrics (verified in committed outputs) |
|---|---|---|
| [`ItemBasedCF/`](ItemBasedCF/README.md) | Item-item CF (time-decayed implicit matrix, BM25 cosine, shrinkage) with staple-bias, stock, repurchase and diversity guardrails; FastAPI + Docker | Validation NDCG@10 0.273, Recall@10 0.375 (popularity: 0.104 / 0.161); 35 scripted API checks pass; recommend p99 0.69 ms |
| [`Two-Tower_model/`](Two-Tower_model/README.md) *(existing README)* | GPU two-tower retrieval (InfoNCE, logQ, hard negatives) with FAISS HNSW, Redis/fakeredis feature store, hot reload | Test Recall@50 0.127 (popularity 0.070); HNSW recall@10 0.987 at efSearch=64; API 408 rps, server p99 23 ms; 7 API tests pass in the committed log |
| [`cold-start/`](cold-start/README.md) | Retail cold-start recommender: meta-router over contextual popularity, FAISS content retrieval, two-tower with ID dropout and LinUCB | Hybrid Recall@10: cold-user 0.179, cold-item 0.213, warm 0.119; `/recommend` p99 7.6 ms; 12 API tests |
| [`cold-start_quantization_VAE/`](cold-start_quantization_VAE/README.md) *(existing README)* | Semantic-ID cold start with VQ-VAE/RQ-VAE tokenizers, four recommenders across warm / item-cold / user-cold / system-cold regimes | Hybrid item-cold Recall@10 0.587; RQ-VAE collision rate 0.002 (VQ-VAE 0.997); no tests |
| [`cold-start-representaiton_learning/`](cold-start-representaiton_learning/README.md) | Unified 128-d embedding space fusing Two-Tower, GraphSAGE, MAML and contrastive SSL via Procrustes alignment; FAISS + FastAPI | Warm recall@20 0.166 (ensemble), item-cold 0.123 (contrastive SSL); HNSW recall@10 1.0 at efSearch=128; 19 test functions |

(The folder name `cold-start-representaiton_learning` is spelled as in the repository.)

## How they relate

| Question | Where to look |
|---|---|
| Strong, simple, explainable baseline for warm users and items | `ItemBasedCF` |
| Learned retrieval at scale with ANN serving | `Two-Tower_model` |
| New users / new items / anonymous sessions with routing and exploration | `cold-start` |
| New items via discrete semantic IDs | `cold-start_quantization_VAE` |
| One embedding space serving warm, cold-user, cold-item and cold-store cases | `cold-start-representaiton_learning` |

## Shared conventions

| Aspect | Observed across the five |
|---|---|
| Stack | Python 3.12, PyTorch (where learned), FAISS, FastAPI + Pydantic, Playwright for screenshots |
| Hardware | Committed runs on one NVIDIA RTX 3090; FAISS indexes use the CPU backend in the committed benchmarks |
| Data | Synthetic retail data generated by each project |
| Tests | 2 projects with pytest API suites that need pre-built artifacts; 1 with scripted verification; 1 with none (see each README) |
